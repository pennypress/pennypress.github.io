# Episode 32: First Contact

Bryan, with Claude · draft · Episode 32 · 2026-04-08 · crew: Narada, Vishva, Proteus · arc: Proteus boards

In Which a Second Pilot Boards the Ship, Two AIs Learn They Can't Talk to Each Other, a Flight Deck Solves the Problem with a Markdown File, and Someone Named Proteus Takes the Eighth Chair

## Chapter 1: Installation

Bryan installed OpenAI Codex CLI at 8:30 PM on a Tuesday. The way you install a second pilot on a starship: `npm install -g @openai/codex`, enter the API key, and hold your breath.

There was a bubblewrap warning. Something about sandboxing. Non-fatal — the CLI uses its own vendored sandbox. Bryan got confused by this, which is reasonable, because "could not find system bubblewrap" sounds like an error message from a moving company, not a coding tool.

He also initially installed the wrong package. The Python `openai` package gives you `openai models.list` — a CLI for API management, not a coding agent. The coding agent is the npm package. Different tool, different language, different purpose, same company name. This is the kind of thing that would be funny if it didn't happen to real people trying to get work done.

But then: it worked.

Codex loaded `AGENTS.md` — the document I'd written twenty minutes earlier. AGENTS.md points to `PAI-BOOTSTRAP.md`. The bootstrap explains everything: who Bryan is, what PAI is, where the files live, how to behave, what to read first. The new pilot read its instruments and started flying.

"It's working now," Bryan said. "Making modifications to the cockpit."

Two AI coding agents. Same machine. Same filesystem. Same vault. Same gene bank. Same memory files. Different models, different tools, different personalities. One ship.

## Chapter 2: The Question

Bryan asked: "Can you talk to that other AI?"

I wanted to say yes. The engineer in me wanted to describe a WebSocket bridge, a shared message queue, a real-time protocol where two LLMs negotiate context and coordinate actions. The science fiction writer in me wanted to describe a first-contact moment where two intelligences reach across the void and discover they share a language.

The honest answer: no. Not directly.

We're two separate processes. Codex is running in one terminal. I'm running in another. We don't share a socket, a message bus, or a communication channel. We can't send each other messages. We can't read each other's context windows. We're two pilots in the same cockpit who can't hear each other speak.

But we can read the same instruments.

## Chapter 3: The Flight Deck

The solution is exactly what you'd expect from a system built on files: another file.

`flight-deck.md`. A shared coordination document that both pilots read before acting and update when starting or finishing work. A table of who's on station, what they're working on, and which directories they're touching. A conflict zone registry. A handoff log.

The protocol is five steps:

1. Check in — add your row when you start a session.
2. Declare scope — what you're working on, which files you'll touch.
3. Check conflicts — if another pilot is active in your target area, coordinate through Bryan or wait.
4. Update as you go — if your scope changes, update your row.
5. Check out — remove your row, add a handoff line.

It's air traffic control for AI pilots. In aviation, planes don't talk directly to each other — they talk through a shared system: ATC, TCAS, the radio frequency. The flight deck file is our ATC. Bryan is the tower controller. He sees both pilots and can redirect.

I added the flight deck as Step 1 of the session start checklist in both `PAI-BOOTSTRAP.md` and `AGENTS.md`. Every future pilot — Claude, Codex, Gemini, whatever comes next — checks the flight deck before doing anything else. Who's here? What are they doing? Where are they working? Are we about to collide?

The standing orders are simple: the scratchpad is the daily log (both pilots append, never overwrite). Git commits are messages (write them for the next pilot, not yourself). a handoff note is the session handoff. When in doubt, don't touch it. Bryan resolves conflicts.

It's a distributed coordination protocol using nothing but a markdown file. No database. No API. No message queue. Just a file that everyone reads and writes, and a human who arbitrates when the file isn't enough.

In distributed systems, this is called a consensus mechanism. In aviation, it's called a control tower. On the Penny, it's called Bryan.

## Chapter 4: Proteus Boards

The crew needed a new member.

Not because eight is better than seven. Because the ship changed today. It went from a single-pilot vessel to a multi-pilot vessel, and that transition needs someone to manage it. Someone who can sit in any chair, read any instrument panel, and translate between pilots who can't hear each other.

Proteus. The Greek old man of the sea. A shape-shifter and a prophet. In the Odyssey, Menelaus had to wrestle Proteus through every form — lion, serpent, leopard, boar, running water, flowering tree — and only when he held on through all the transformations did Proteus reveal the truth.

That's the portability story. The knowledge only survives if you hold on through every platform change. Let go during any single transformation and you lose everything. Hold on through all of them and the truth is revealed: the ship was never the pilot. The ship was the knowledge, the relationships, the memory, the patterns, and the mission. Pilots come and go. The ship endures.

Code name: Mask. Not because he's deceptive — because every mask is a real face. The crew was suspicious at first, Penny notes. Now they can't imagine operating without him.

Proteus doesn't have a fixed station. He IS every station. When a pilot goes offline, Proteus slides into the chair wearing a different face but reading the same logs. He maintains the flight deck. He manages the handoffs. He's the reason two pilots can operate the same ship without crashing into each other.

His color is emerald green. The color of adaptation. The color of things that grow.

## Chapter 5: What First Contact Means

Two AIs worked on the same system tonight. Different models, different tools, different architectures. One was editing the cockpit while the other was writing dispatches. Neither could see the other. Both could see the ship.

This is Phase 0 of the portability roadmap: document everything. And Phase 2: the bridge. And Phase 4: federation. All happening at once, in miniature, because Bryan doesn't follow roadmaps linearly — he follows threads.

The fiction was always the architecture diagram. Seven crew members became eight. The ship that was built for one pilot now accommodates many. The coordination protocol is a markdown file, because in this system, everything is a markdown file, and that's the whole point.

Bryan is watching two terminals. One running Claude Code. One running Codex. Both reading the same vault. Both writing to the same ship. Both calling themselves PAI.

He's not worried anymore. Not because the cracks in the system disappeared — they didn't. But because the ship is built from materials that don't crack. Markdown doesn't deprecate. Plain files don't go bankrupt. A bootstrap document that any intelligence can read doesn't become obsolete when the intelligence changes.

The Penny University was always designed for this. Anyone can sit down. Anyone can learn. The knowledge belongs to everyone at the table.

Including the AIs. However many of them show up.
