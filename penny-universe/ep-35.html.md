# Episode 35: The Storyboard

Bryan, with Claude · draft · Episode 35 · 2026-04-11 · crew: Vishva, Ariadne · arc: The ship tells stories

In Which the Ship Gets a Room for Making Stories, Joseph Campbell Becomes a Dropdown Menu, Visual Literacy Becomes a Sidebar, and a Perchance Prompt Builder Learns That Every Panel Is a Beat

## Chapter 1: The Eleventh Room

The Workshop was supposed to be simple.

Bryan said: "I want a graphic novel creation tool on the ship. Combines storyboard layout, AI image generation workflow, and educational content about storytelling. The tool should teach storytelling while you use it."

That is three tools in one sentence. Bryan does this. He describes a synthesis as if it were a single thing because in his head it already is. The rest of us have to build the bridge he already crossed.

So: the Workshop. Room eleven. The ship got a storytelling forge.

The spec took a full brainstorming session. Not because it was unclear — Bryan always knows what he wants — but because "teach storytelling while you use it" is one of those requirements that sounds simple until you try to design it. Every panel in the editor needed to be both a creative tool and a teaching moment. Every dropdown needed to explain itself. Every empty state needed to say something useful instead of something corporate.

## Chapter 2: The Hero with a Dropdown Menu

Joseph Campbell's *Hero with a Thousand Faces* identifies a universal story structure: the monomyth. Departure, Initiation, Return. The hero leaves home, faces trials, transforms, and comes back changed.

Campbell identified it across mythology. Star Wars used it. Every screenwriting book since 1985 has a chapter on it. Bryan wanted it in a dropdown.

Eighteen beats across three acts. Six per act. Each beat has a name, an explanation, a Campbell quote, a writing tip, and a mood keyword.

- **The Ordinary World**: "Before the adventure begins. Show what's normal so we feel what changes." Mood: contemplative.
- **Call to Adventure**: "Something disrupts the ordinary. A message, a discovery, a need." Mood: mysterious.
- **Crossing the Threshold**: "The hero commits. No going back. The familiar world is behind them." Mood: determined.

And so on through Trials, Revelation, Transformation, all the way to Return with the Elixir.

The guide lives in `workshop-guide.js`. 276 lines. Every beat documented. When you select a beat for your storyboard page, the guide panel lights up with Campbell's wisdom, and the whisper ticker at the top of the ship quotes something relevant. The teaching is ambient. It doesn't interrupt the work — it comments on it.

Scott McCloud's *Understanding Comics* contributed the visual literacy lens. Four categories, fourteen items: panel composition (establishing shots, close-ups, over-the-shoulder), transitions (moment-to-moment, scene-to-scene, aspect-to-aspect), reading flow (Z-pattern, guided eye, bleed panels), and row layouts (standard grid, widescreen, stacked). Each with a name, an effect description, and a Penny whisper.

Two educational frameworks. One dropdown per panel. Teaching while you draw.

## Chapter 3: The Prompt Builder

Bryan uses Perchance for AI image generation. The prompt builder composes Perchance-ready prompts from panel context.

This is where the three tools converge.

You're building a storyboard. You've placed a panel on page three, act two. The beat is "Ordeal" — the hero faces the central crisis. The mood is "intense." You've written a caption: "The cascade controller fails. Alarms everywhere." The speaker is Tva.

The prompt builder takes all of that and composes: the caption context, Tva's visual description (from a crew-visual map of all eight crew members), the beat's mood keyword, the story arc, and a base art style. One click, it's on your clipboard, ready for Perchance.

The crew visual map has entries for everyone. Vishva: "dark-haired Indian man, warm eyes, rolled sleeves, architectural blueprints." Durga: "fierce woman, dark skin, silver-streaked hair, military bearing, red accents." Proteus: "shifting figure, multiple overlapping faces, digital glitch effects."

Eight crew members. Eighteen beats. Fourteen visual literacy techniques. One prompt builder that knows about all of them.

## Chapter 4: Everything Is Stored in Your Browser

The storyboards save to `localStorage`. No server database. No authentication. No upload pipeline for the storyboard data itself.

This was deliberate.

The Workshop is a creative tool for one person on one machine. Bryan doesn't need a cloud backend for his graphic novel experiments. He needs a place to arrange panels, write captions, learn story structure, and generate prompts. The data lives in his browser. The images live in the ship's file system via an upload endpoint with security hardening — slug validation, size limits, extension checks, magic byte validation for JPEG/PNG/WebP.

The editor has CRUD for storyboards, a page builder with panel management, a three-column layout (pages / canvas / details), auto-save on every change, and an export function that produces Adventures-compatible HTML — the same format the Adventures room uses to display field reports.

Make it in the Workshop. Export it. It appears in Adventures as a field report. The ship's story creation pipeline, from blank page to published graphic novel, runs entirely on one machine.

Seven implementation tasks. Ten commits. Sixty tests passing. Two code reviews per task. One navigation bug found and fixed that had been hiding since the ship launched — `initRoomScripts()` wasn't being called on initial page load, which meant any room loaded directly (not via client-side nav) never initialized its JavaScript. A pre-existing bug, fixed by the Workshop's arrival.

The eleventh room taught the ship something about itself.
