Software Is Not Property, It's a Potluck Plate

An outline, thinking in the open

By Bryan, with Claude · outline · claims ledger

This is an outline, not an essay yet. We publish it to think in the open: the argument's shape, the pushback we already have, and what we still need to find out.

The claim, in one sentence

Intellectual-property law treats software as a durable thing that can be owned, but software has stopped being that kind of thing: it is the trace of a person's judgment, cheap to regenerate, and the value lives in the judgment, not the trace.

Bryan, the day the outline started: "IP treats software as this property that it is not its reified in a way that is not substantiated any longer software is disposable."

1. The plates at the potluck

  • Open on the image: "software is paper plates at a pot luck where people solve real problems." Plates are necessary and disposable, and nobody comes to the potluck for them. The food is the problem-solving.
  • A worked example: PartsLoc, a parts-inventory app a technician built with an AI and is releasing free under GPL-3.0. Its code could be rebuilt from his direction. What could not be rebuilt is knowing which shelf count is lying.

2. When the copy was the value

  • Why property made sense: the press, the pressing plant, the boxed disk. Copying was costly, so owning the copy meant owning the value.
  • What changed: copying went to zero first. Now making is going toward zero for a growing class of tools, because a model can write what a person can clearly ask for.
  • The word for the mistake: reification, treating a process as if it were a thing. (To check: the term's history, from Lukács, and whether it is the right one or only a near one.)

3. What the code actually is

  • A trace of a conversation: direction, then generation, then correction, saved to disk. The saved file is the residue. The thing that made it is still walking around.
  • The test: clone the repository, and you get the residue. You do not get the person who knew what to ask for, what to catch, and when "done" is a lie.
  • Link back to the Compassion bush: the same move as treating a person as "a static thing" instead of as capable of growth.

4. Pushback, taken seriously

  • The fiction still binds. Employers, courts and app stores act on it. Before releasing PartsLoc, a technician still had to read his employer's IP policy and write a note to send. The essay should show that cost, not wave it away.
  • Copyleft is judo. The GPL uses the property system against itself: it claims ownership so that no one can enclose the code. If software must be property, this is property that keeps refusing to be owned. (To check: how the GNU project itself describes copyleft.)
  • Disposable is not worthless. A bad plate spills the food. Quality still matters; it just isn't where the value lives.
  • Who this hurts. People who make their living selling code as an object. Say this plainly, and ask what they sell instead: maintenance, trust, the craft.

5. What is durable, then

  • The data people put in: their shop, their counts, their history. That is theirs, and a good tool lets them leave with it.
  • The trust that the tool does what it says: an honest privacy page, a published audit, claims anyone can check.
  • The craft of knowing what to build: the flight line, the shop floor, the years.
  • Close: give away the plates. Keep cooking.

Still to find out before draft 1

  • Is "reification" the right word, or is a plainer one better?
  • What does copyright law actually protect in software? Its expression, not its ideas: check the statute and one case, and quote them exactly.
  • Has anyone made this argument well already? Read them first, and cite them or say how this differs.
  • One counter-example where the code really is the value (a hard algorithm, a format everyone depends on), and what it does to the claim.
